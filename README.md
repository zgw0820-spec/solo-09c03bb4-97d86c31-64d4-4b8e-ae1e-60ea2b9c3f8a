# RAID 5 单盘故障演练平台

面向机房值班员的 RAID 5 单盘故障演练：3 个本地文件模拟 3 块盘，4 个条带、
校验块在盘间轮换（异或校验），网页上可完成「摘盘 → 降级读写 → 逐条带重建
→ 注入重建失败 → 重试 → 换盘完成 → 再摘另一盘核对」的完整流程。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发（不用 Docker）：

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
DATA_DIR=./data .venv/bin/uvicorn app.main:app --port 8000
```

## 阵列布局

- 每盘一个文件（`data/diskN.img`），4 块 × 4096 字节
- 4 个条带，每条件 2 数据块 + 1 异或校验块，共 8 个逻辑块（0~7）
- 校验块轮换（左对称）：条带 0→盘2，条带 1→盘1，条带 2→盘0，条带 3→盘2

| 条带 | 盘0 | 盘1 | 盘2 |
|---|---|---|---|
| 0 | 块0 | 块1 | P |
| 1 | 块2 | P | 块3 |
| 2 | P | 块4 | 块5 |
| 3 | 块6 | 块7 | P |

## 演练流程

1. **摘盘**：阵列健康时可摘除任意一盘，进入降级运行
2. **降级读写**：按逻辑块号读写不受影响；落在缺失盘上的块由同条带
   「校验块 ⊕ 另一数据块」实时重构；写入缺失盘上的块时，新数据折入校验块
3. **重建**：换上替换盘，逐条带重建（自动 0.8s/条带，或手动单步）。
   重建途中可继续读写，包括已重建的条带（写入会同步到新盘已重建部分）
4. **故障注入**：开始重建时可指定某一条带写新盘失败。失败后替换盘作废，
   阵列保持降级读写，已确认的写入不受影响，可重试重建
5. **换盘完成**：4 个条带全部补齐最新内容后才显示完成；此后可再摘另一盘
   核对数据（阵列只允许在健康时摘盘，防止误摘第二块造成数据丢失）

## 状态持久化

槽位状态与重建进度写入 `data/meta.json`。服务重启时：进行中的重建按
失败处理（替换盘内容不可信，丢弃），阵列回退到降级状态，可重试重建。

## 测试

```bash
.venv/bin/python -m pytest tests/ -q
```

覆盖：条带映射、降级读写、完整重建、重建途中写入（已重建/未重建条带、
落在重建盘上的块）、注入失败与重试、再摘另一盘核对、重启恢复、API 端到端。

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/status` | 阵列/磁盘/条带/重建状态与日志 |
| POST | `/api/reset` | 重置阵列并写入演示数据 |
| POST | `/api/disks/{n}/remove` | 摘除盘 n（仅健康时允许） |
| POST | `/api/rebuild/start` | 开始重建 `{fail_at, auto, delay}` |
| POST | `/api/rebuild/step` | 手动单步重建一个条带 |
| GET | `/api/blocks/{n}` | 读逻辑块 n |
| PUT | `/api/blocks/{n}` | 写逻辑块 n `{text}` 或 `{hex}` |
| GET | `/api/blocks` | 读全部 8 个逻辑块 |
